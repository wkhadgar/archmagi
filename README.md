## Requirements

Get the AUR manager (here, paru for compatibility):
```bash
sudo pacman -S --needed base-devel git
git clone https://aur.archlinux.org/paru.git
cd paru
makepkg -si
```

Then, get the packages:
```bash
sudo pacman -S --needed - < requirements.pacman
```

## Install

Each MAGI machine has its own branch (`melchior-1`, `casper-3`, `balthasar-2`) carrying host-specific tweaks (monitors, hostname, fastfetch footer, etc.). Check out the matching branch first, or stay on `main` for a fresh host.

```bash
git clone https://github.com/wkhadgar/dotfiles
cd dotfiles
git checkout <hostname>          # e.g. melchior-1 — or skip for main
source ./import_dotfiles.sh
chsh -s $(which zsh)
```

## The `magi` CLI

After install, `magi` lives at `~/.local/bin/magi` (a thin dispatcher) with its command libraries under `~/.local/bin/magi.d/` (sourced on demand). Run `magi help` for the full list. Highlights:

- `magi status` — NERV-themed system overview (host, uptime, tailnet, updates, CPU/MEM/DISK/NET)
- `magi update [run|check [-j]]` — interactive `paru -Syu` wrapper (`run` is the default); `check` returns pending count
- `magi cheatsheet` — rofi popup of all Hyprland keybindings (also bound to `SUPER+/`)
- `magi tmux <attach|list|switch|detach|kill>` — tmux session control (default session name `MAGI`); `switch` uses fzf to pick
- `magi lock` / `reboot` / `exit` / `shutdown` — power actions, gated by the MAGI consensus dialog. The exit/reboot/shutdown trio chain through `hyprshutdown` (pulled in by `requirements.pacman`) so apps close cleanly before the system command fires.
- `magi restart <waybar|xdph>` — kill + relaunch a desktop service
- `magi install boot` — install NERV bootloader theme; auto-detects GRUB (writes `/etc/default/grub` + runs `grub-mkconfig`) or limine (drops a managed `# >>> magi boot` block into `/boot/limine.conf`).

The boot wallpaper at `/usr/share/nerv/boot-background.png` is generated by `/usr/share/nerv/regenerate-bg.sh [WIDTHxHEIGHT]` (default `1920x1080`) and is read by both GRUB and limine. On a host with a non-1080p display, regenerate before installing:

```bash
/usr/share/nerv/regenerate-bg.sh 2560x1440   # or whatever the panel is
magi install boot
```

## Testing

Before deploying changes to `magi`, run the smoke test against the in-repo version:

```bash
tests/smoke.sh
```

It bash-syntax-checks every shipped script, sources each `magi.d/<group>.sh` to confirm the expected `cmd_*` functions are defined, and end-to-end-invokes the safe-to-call commands (`help`, `status`, `tailnet`, `update check`). Destructive commands (`reboot`, `restart waybar`, `install boot`, etc.) are only checked at the function-defined level — never actually invoked. `PATTERN GREEN` on full pass; `PATTERN RED` with details on failure.

To run it automatically before every commit that touches `bin/magi*` or the test itself, enable the tracked pre-commit hook **once per clone**:

```bash
git config core.hooksPath .githooks
```

Bypass for a single commit with `git commit --no-verify`.

## Post-install

- Enable greetd: `sudo systemctl enable greetd`
- Check monitor names with `hyprctl monitors | grep Monitor`, then update **both** `hypr/hyprland/monit.conf` (resolution/position/scale that Hyprland actually uses) and `hypr/hyprpaper.conf` (wallpaper bindings per monitor)
- Apply the NERV bootloader theme (optional): `magi install boot` (works for GRUB and limine)
- `atuin` must remain the last line of `.zshrc`
